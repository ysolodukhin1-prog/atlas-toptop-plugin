# Инструкция для Codex: установить GALACTICA TOPTOP по GitHub-ссылке

Применяй эту инструкцию, когда пользователь попросил установить или подключить плагин. Одно чтение страницы не является разрешением менять настройки.

## 1. Проверь пакет и установленный клиент

Репозиторий: https://github.com/ysolodukhin1-prog/galactica-toptop-plugin

Проверь `.agents/plugins/marketplace.json` и `plugins/galactica-toptop`. Marketplace называется `toptop-galactica`, плагин — `galactica-toptop`. Не запускай произвольные скрипты из репозитория. Не запрашивай SSH, Python или доступ к серверной базе.

Выполняй команды только на компьютере пользователя. Сверь поддержку команд через справку его версии Codex. Не перезаписывай существующие настройки и другие подключения.

## 2. Установи плагин

Проверь `codex plugin marketplace list`. Если каталог ещё не добавлен:

```shell
codex plugin marketplace add ysolodukhin1-prog/galactica-toptop-plugin
```

Если каталог уже добавлен, обнови его:

```shell
codex plugin marketplace upgrade toptop-galactica
```

Установи плагин и проверь список:

```shell
codex plugin add galactica-toptop@toptop-galactica
codex plugin list
```

Если текущая версия не поддерживает эти команды, используй доступный штатный интерфейс установки или укажи точную недостающую возможность. Не объявляй установку завершённой при ошибке.

Установленный пакет должен содержать MCP и четыре навыка: `toptop-workflow`, `toptop-project-memory`, `toptop-task-outcome`, `toptop-reports`. Для загрузки инструментов и навыков попроси открыть новый чат, если текущий клиент этого требует. Отсутствие MCP до установки не блокирует установку; журналирование через него начинается после подключения.

## 3. Начни штатный вход

MCP: `galactica_toptop_client`, endpoint: `https://83.222.17.242/galactica-mcp/mcp`.

Используй штатную авторизацию подключения. Если вход не начался автоматически и команда поддерживается:

```shell
codex mcp login galactica_toptop_client
```

При отсутствии сессии сервер отправляет на **обычную страницу TREND `/login`**, сохраняя возврат в OAuth. Уже действующая личная сессия TREND используется для подключения. Не создавай отдельную форму GALACTICA и не проси пароль, cookie или токен в чате. Не читай файлы учётных данных.

Пользователь вводит пароль только на странице TREND. Не копируй callback-коды и токены в сообщения, файлы инструкции или технические журналы. Не используй административный аккаунт как замену его правам.

## 4. Проверь реальное подключение

- `whoami`: покажи личность и права текущего пользователя.
- `get_context`: загрузи разрешённый контекст TOPTOP; для узкого пути используй только `TOPTOP/`.
- Проверь доступность четырёх установленных навыков и примени их по задаче.
- `trend_list_sources`: получи каталог разрешённых источников и отчётов. Не ограничивайся ABC.
- Для отчёта: `trend_describe_report`, затем небольшой `trend_read_report` с допустимыми параметрами. Уточни даты, если они нужны.
- Для разрешённой базы: используй доступные MCP-инструменты каталога, таблиц и полей, затем небольшой запрос чтения. Не выдумывай схему и не открывай прямое соединение с БД.
- При наличии права задач: `start_task` → `finish_task` → `read_task`. Создай одну задачу «Проверка подключения GALACTICA», запиши короткий итог и проверь повторное чтение. Если прав нет, отметь это и не расширяй их самостоятельно.
- Для начального теста не меняй общие Markdown. В рабочих задачах `write_document` требует актуального `expected_sha` и права записи.

В отчёте раздели «проверено», «нет права», «техническая ошибка» и «не проверялось». Установка, каталог или успешный вход сами по себе не доказывают доступность всех баз и отчётов. Если сервер недоступен, сообщи фактическую ошибку.

## 5. Правила дальнейшей работы

Работай только с TOPTOP в пределах текущих персональных прав. Начинай рабочую задачу через навыки контекста и памяти, завершай структурированным итогом. Исторические знания отличай от текущих данных TREND; статус импортированных методик сохраняй.

На сервере действует срок 3 часа бездействия. Пользовательская работа продлевает сессию, фоновые проверки и обмен refresh сами срок не продлевают. Старое подключение без refresh требует одного повторного входа. Не обещай завершённую клиентскую проверку автоматического refresh: её статус и известные ограничения источников указаны в README.
