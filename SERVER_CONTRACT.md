# Серверный контракт GALACTICA TOPTOP

## Граница доверия

Клиент устанавливает плагин из GitHub marketplace GALACTICA. Плагин содержит URL `https://83.222.17.242/galactica-mcp/mcp` и навыки; живые данные и права остаются на сервере. Сервер реализует MCP Streamable HTTP и OAuth 2.1 Authorization Code + PKCE поверх личного входа TREND. Пользователь имеет явные права GALACTICA TOPTOP в TREND; действующая сессия и права TOPTOP проверяются при выдаче токена **и на каждом вызове**. Токен имеет audience MCP GALACTICA TOPTOP, короткий срок жизни и отдельные scopes `toptop:read`, `toptop:task`, опционально `toptop:write`. Отзыв пользователя, сессии или членства прекращает доступ без ожидания истечения токена.

Публичный endpoint публикует OAuth Protected Resource Metadata и Authorization Server Metadata. `401` содержит `WWW-Authenticate` с `resource_metadata`. Код согласия одноразовый, связан с `client_id`, `redirect_uri`, `resource` и PKCE challenge; динамическая регистрация клиентов или CIMD поддерживается явно. Токены, коды и verifier никогда не попадают в Markdown, журналы задач или ответы MCP.

Сервер связывает каждую операцию с подтверждёнными `user_id`, `project_id`, `client_id`, `scopes`. Значения `agent_id`, `project_id` и роль из аргументов инструмента не считаются авторизацией. Оба помощника используют общий вход TREND/GALACTICA TOPTOP. Уже открытая личная сессия TREND используется без второго пароля. Внутренний GALACTICA principal создаётся как проекция подтверждённого ID TREND, без local_login. Каждое OAuth-подключение связано со своей исходной зашифрованной сессией; новый вход не оживляет отозванный токен. Права `context`, `tasks`, `markdown` выдаются в источнике `galactica:toptop` управления пользователями TREND. Доступ к каждому отчёту дополнительно требует TOPTOP, права на этот отчёт и соответствующего ресурса `marketplace:toptop`. Общий администраторский cookie не заменяет личный вход. Локальная блокировка GALACTICA также учитывается. Права источника проверяются до и после чтения. PostgreSQL `galactica_autonomy` — канон знаний; Qdrant и Neo4j — индексы. Access-токен MCP действует до 3 часов в пределах исходной сессии. Реализован refresh с ротацией и отзывом семейства при повторном использовании. Срок исходной сессии — 3 часа бездействия; успешные операции MCP и действия пользователя в веб-интерфейсе продлевают её. Ping, список инструментов, фоновый опрос и refresh не продлевают срок бездействия. Старое подключение без refresh требует одного повторного входа. Реальная автоматическая ротация клиентом пока требует завершения проверки.

## Инструменты первой версии

| Инструмент | Право | Контракт |
| --- | --- | --- |
| `whoami` | read | Личный ID, TOPTOP, scopes, срок сессии; без токена |
| `get_context` | read | Наследуемые Markdown для указанного пути, версии и SHA каждого документа; ограничение размера |
| `search_knowledge` | read | Поиск в пределах TOPTOP; ID, вид, эпистемический статус, источник, версия, фрагмент |
| `get_knowledge` | read | Каноническая строка PostgreSQL по ID; при отсутствии доступа 404 |
| `list_skills` / `get_skill` | read | Только активные процедуры GALACTICA и отдельно помеченные кандидаты; источник, версия, статус проверки |
| `start_task` | task | Идемпотентный UUID, запрос, критерии, точный источник, actor из токена |
| `record_message` | task | Только точный доступный текст с источником; частичное/отредактированное помечать |
| `finish_task` | task | Структурированный аутком по существующей схеме; неизменяемый итог и очередь протоколайзера |
| `read_task` | read | Только собственная задача и сохранённый итог |
| `trend_read_abc` | read | Совместимость: разрешённые ABC summary/stats Ozon/Wildberries |
| `read_document` | read | Текущий Markdown, logical key, версия, SHA |
| `write_document` | markdown | Журналируемая запись с expected SHA и task ID; 409 при конфликте; отдельное право |

`reconcile`, `import_canonical`, `accept_import`, администрирование навыков и доступ к чужим проектам не входят в клиентский набор. Материнские методы отчётов — справочные кандидаты с происхождением, а не активные инструкции без проверки. Если пользователь запросит правку Markdown, её право выдаётся отдельно. Никаких прямых SQL, произвольных путей, SSH и универсального `run_command` у клиента нет.

## Результаты внедрения

Развёрнуты HTTPS MCP, OAuth PKCE и DCR, проверка личности и членства при каждом вызове, адаптер канонических знаний и задач, журналируемый Markdown и личный доступ TREND. Отдельный пользователь прошёл полный сценарий в настоящем Codex: установка, вход, контекст, знания и навыки, текущие данные, задача, запись, итог и повторное чтение. Проверены запреты без входа, чужой задачи/клиента, старого SHA и отзыв прав. Установка Claude Code проверена; полный сценарий выполнения задачи в Claude Code отдельно не проверен. Сохранение итога подтверждено, завершение дальнейшей обработки протоколайзером не проверено. Время обновления данных источника пока не подтверждено.

**Права в TREND:** context → reader; context + tasks → contributor; context + tasks + markdown → manager. Отдельный local_login не создаётся. Отключение личного пользователя, отзыв сессии или разрешений TREND прекращает доступ MCP. Локальная блокировка GALACTICA дополнительно запрещает доступ. Установка не выдаёт права. Codex CLI запускается только на ноутбуке. PULSE КОКОС не является источником TOPTOP.

## Персональные источники и отчёты

- `trend_list_sources`: текущий каталог отчётов, баз и методов по персональным правам TREND.
- `trend_describe_report`, `trend_read_report`: параметры и чтение выбранного разрешённого отчёта.
- `trend_list_databases`, `trend_list_tables`, `trend_describe_table`, `trend_query_database`: разрешённые подключения и ограниченный SELECT с фильтрами и агрегатами.
- `trend_list_source_methods`, `trend_read_source`: опубликованные методы GET MPStats, разрешённые в TREND.

Контур фиксирован TOPTOP. Права читаются из действующей админки TREND до выполнения и перед выдачей; отдельной копии прав в плагине нет. Знания/задачи/Markdown имеют отдельные права. Источники с технической ошибкой не исчезают из каталога. reason_code сообщает тип отказа без секретов.

Ограничения: отчёт/MPStats — не более 800 КБ, до 200 строк в массиве и 2000 элементов всего, обрезка обозначена явно; worker 28 с. Базы — SELECT одной таблицы до 500 строк, SQL 10 с/worker 17 с. Период отчёта до 366 дней. Произвольные SQL, JOIN и запись запрещены. Каталог MPStats основан на официальных спецификациях 25.09.2026; доступ внешнего тарифа проверяется вызовом.

## Единая страница входа

Неавторизованный OAuth-запрос перенаправляется на штатный TREND `/login?next=…` с сохранением параметров возврата. Старая MCP login-ссылка также перенаправляет туда; POST старой формы удалён (410) и не обрабатывает пароль. Истёкшая сессия ведёт на вход, недостаток прав при действующей сессии — к отказу, без цикла перенаправлений. Проверки PKCE, зарегистрированного callback и личных прав сохраняются.


## Codex desktop: HTTPS-возврат во встроенный браузер

Для сценария BROWSER_AUTH.md развёрнут GET `/galactica-mcp/oauth/codex-callback` с необязательным суффиксом ID клиента (8–128 символов A–Z, a–z, 0–9, `_`, `-`). Сервер отдаёт нейтральную страницу ожидания с `Cache-Control: no-store`, CSP без скриптов/внешних ресурсов и запретом встраивания. Query на странице возврата отклоняется.

Только для этого точного HTTPS origin/path OAuth redirect переносит одноразовые `code/state` из query во fragment. Они не отправляются HTTP-запросом странице возврата. Помощник преобразует их обратно в query в памяти и передаёт штатному `codex mcp login --no-browser` через stdin pipe. PKCE, state, зарегистрированный redirect URI, права пользователя и одноразовость кода проверяются прежним механизмом. Токены не выдаются странице браузера.

Автоматический переход применяется только при `Sec-Fetch-Site: none` или `same-origin`, как в существующем локальном сценарии. Произвольный чужой HTTPS callback не получает автоматического согласия. Обычные loopback callback других клиентов остаются совместимыми. Страница ожидания не утверждает, что токен уже получен: завершение проверяет CLI, затем `whoami`.

Параметры callback задаются временно только для команды входа. Они не подменяют MCP endpoint, не расширяют права и не требуют изменения учётной записи TREND. Выбор встроенного браузера и открытие рабочих вкладок выполняются средствами Codex desktop; один сервер MCP не управляет браузером клиента.
