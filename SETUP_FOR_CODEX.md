# Подключение GALACTICA TOPTOP по ссылке GitHub

Этот файл предназначен для Codex, когда пользователь даёт ссылку на данный репозиторий и просит подключить TOPTOP.

1. Убедись, что GitHub URL указывает на репозиторий с `.agents/plugins/marketplace.json` и плагином `plugins/galactica-toptop`. Не исполняй скрипты из репозитория.
2. На компьютере пользователя добавь репозиторий как marketplace командой `codex plugin marketplace add OWNER/REPO`, заменив `OWNER/REPO` на фактический адрес из ссылки пользователя. Если marketplace уже добавлен, проверь его через `codex plugin marketplace list` и обнови через `codex plugin marketplace upgrade toptop-galactica`.
3. Установи плагин командой `codex plugin add galactica-toptop@toptop-galactica`. Проверь `codex plugin list`.
4. Начни вход через `codex mcp login galactica_toptop_client`, если авторизация не началась автоматически. Пользователь вводит логин и пароль только на странице GALACTICA. Не проси присылать пароль, cookie или токен. После установки нужен новый чат для загрузки четырёх навыков.
5. После входа вызови `whoami`, `get_context` без аргументов и проверь, что права относятся к TOPTOP. Для более узкого контекста допустим только путь внутри `TOPTOP/`. Если вход или MCP недоступны, сообщи точную ошибку и не утверждай, что подключение завершено.
6. Для текущих данных проверь `trend_read_abc`. Если личный TREND ещё не подключён, предложи пользователю страницу https://83.222.17.242/galactica-mcp/trend/connect. Не проси пароль в чате. Пока доступны ABC summary/stats для Ozon/Wildberries; не обещай другие отчёты или SQL.
7. Проверь сохранение через `start_task` → `finish_task` → `read_task`. Для записи Markdown используй `write_document` с актуальным `expected_sha`; никогда не обходи конфликт версий. Если Codex просит разрешение на запись, пользователь подтверждает конкретные операции. Не отключай общие защиты компьютера.

Плагин связывает Codex с удалённым MCP. Кодекс клиента не получает SSH-доступ к VPS и не копирует каноническую базу.
