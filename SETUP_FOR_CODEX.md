# Инструкция для Codex: установить GALACTICA TOPTOP по GitHub-ссылке

Применяй эту инструкцию, когда пользователь попросил установить или подключить плагин. Одно чтение страницы не является разрешением менять настройки.

## 1. Проверь пакет и установленный клиент

Репозиторий: https://github.com/ysolodukhin1-prog/galactica-toptop-plugin

Проверь `.agents/plugins/marketplace.json` и `plugins/galactica-toptop`. Marketplace называется `toptop-galactica`, плагин — `galactica-toptop`. Не запускай произвольные скрипты из репозитория. Не запрашивай SSH, Python или доступ к серверной базе.

Выполняй команды только на компьютере пользователя. Сверь поддержку команд через справку его версии Codex. Не перезаписывай существующие настройки и другие подключения.

## 2. Установи или обнови плагин

Проверь `codex plugin marketplace list`. Если каталог ещё не добавлен:

```shell
codex plugin marketplace add ysolodukhin1-prog/galactica-toptop-plugin
```

Если каталог уже добавлен, обнови его:

```shell
codex plugin marketplace upgrade toptop-galactica
```

Перед установкой проверь, что обновлённый каталог содержит `authentication: ON_USE`. Сценарий входа входит в пакет: `skills/toptop-workflow/browser-auth.md`. Установка не должна сама запускать внешний браузер. Если каталог всё ещё содержит `ON_INSTALL`, обновление не получено — не продолжай по старому сценарию.

Установи (или переустанови обновлённый пакет) и проверь список:

```shell
codex plugin add galactica-toptop@toptop-galactica
codex plugin list
```

Если текущая версия не поддерживает эти команды, используй доступный штатный интерфейс установки или укажи точную недостающую возможность. Не объявляй установку завершённой при ошибке.

Установленный пакет должен содержать MCP и четыре навыка: `toptop-workflow`, `toptop-project-memory`, `toptop-task-outcome`, `toptop-reports`. Для загрузки инструментов и навыков попроси открыть новый чат, если текущий клиент этого требует. Отсутствие MCP до установки не блокирует установку; журналирование через него начинается после подключения.

## 3. Войди во встроенном браузере Codex

MCP: `galactica_toptop_client`, endpoint: `https://83.222.17.242/galactica-mcp/mcp`.

Сначала прочитай [входящий в пакет сценарий](plugins/galactica-toptop/skills/toptop-workflow/browser-auth.md). При заведомо действующем подключении проверь `whoami`; повторный вход не нужен. При первичном подключении сначала выполни управляемый вход: вызов неавторизованного MCP до этого может запустить штатный внешний браузер. Политика `ON_USE` сама по себе не управляет браузером.

Используй встроенный браузер Codex (`iab`). Запускай команду на компьютере пользователя как живой дочерний процесс с открытым stdin, отдельными stdout/stderr и без терминального эха:

```shell
codex -c 'mcp_servers.galactica_toptop_client.url="https://83.222.17.242/galactica-mcp/mcp"' -c 'mcp_servers.galactica_toptop_client.oauth.callback_url="https://83.222.17.242/galactica-mcp/oauth/codex-callback"' mcp login galactica_toptop_client --no-browser --oauth-client-registration dcr
```

Перед запуском проверь `codex mcp login --help`. Не запускай эту команду через разовый shell с закрытым stdin: она завершится до входа. Не вставляй длинный callback через Windows PTY: при проверке такой ввод терял часть адреса. Используй настоящий pipe, как в BROWSER_AUTH.md. Параметры `-c` действуют только на этот запуск; не заменяй постоянные настройки пользователя.

Открой в `iab` именно свежий authorization URL, выданный этим процессом. При отсутствии сессии сервер отправляет на **обычную страницу TREND `/login`**, сохраняя возврат в OAuth. Уже действующая личная сессия TREND используется для подключения. Не создавай отдельную форму GALACTICA и не проси пароль, cookie или токен в чате. Не читай файлы учётных данных.

Пользователь вводит пароль только на странице TREND. После входа сервер возвращает браузер на HTTPS-страницу «Завершаем подключение». Получи текущий адрес через браузерный инструмент, проверь его соответствие текущему OAuth-запросу и передай одноразовый результат в stdin того же процесса согласно BROWSER_AUTH.md. Не открывай этот результат как новый URL. Не копируй callback-коды и токены в ответы пользователю, файлы или технические журналы. Не используй административный аккаунт как замену его правам.

Дождись успешного завершения команды, затем вызови `whoami`. Если текущий чат ещё держит прежнее подключение, попроси открыть новый чат или штатно переподключить MCP; не повторяй вход бесконечно. Если встроенный браузер, управление им или stdin pipe недоступны, назови конкретное ограничение клиента. Не переключай молча вход во внешний браузер и не обещай, что одна настройка MCP управляет выбором браузера.

## 4. Проверь реальное подключение

- `whoami`: покажи личность и права текущего пользователя.
- `get_context`: загрузи разрешённый контекст TOPTOP без аргумента `path` либо с `path="TOPTOP/CURRENT_TASK.md"`. Для узкого контекста передавай путь к документу внутри TOPTOP, не голый каталог `TOPTOP/`.
- Проверь доступность четырёх установленных навыков и примени их по задаче.
- `trend_list_sources`: получи каталог разрешённых источников и отчётов. Не ограничивайся ABC.
- Для отчёта: `trend_describe_report`, затем небольшой `trend_read_report` с допустимыми параметрами. Уточни даты, если они нужны.
- Для разрешённой базы: используй доступные MCP-инструменты каталога, таблиц и полей, затем небольшой запрос чтения. Не выдумывай схему и не открывай прямое соединение с БД.
- При наличии права задач: `start_task` → `finish_task` → `read_task`. Создай одну задачу «Проверка подключения GALACTICA», запиши короткий итог и проверь повторное чтение. Если прав нет, отметь это и не расширяй их самостоятельно.
- Для начального теста не меняй общие Markdown. В рабочих задачах `write_document` требует актуального `expected_sha` и права записи.

В отчёте раздели «проверено», «нет права», «техническая ошибка» и «не проверялось». Установка, каталог или успешный вход сами по себе не доказывают доступность всех баз и отчётов. Если сервер недоступен, сообщи фактическую ошибку.

## 5. Открой две рабочие вкладки

После завершения попытки OAuth замени её служебную вкладку на [GALACTICA](https://83.222.17.242/galactica/). Открой рядом отдельную вкладку [TREND TOPTOP](https://83.222.17.242/react/?client=toptop&dashboard=home&marketplace=total) в том же встроенном браузере. Сохрани обе как результат для пользователя; повторно используй уже открытые рабочие вкладки, если они есть.

Проверь, что загрузился рабочий интерфейс, а не форма входа или страница ошибки. Ошибка `whoami`, контекста или каталога не блокирует открытие этих вкладок. Отдельно сообщи, что MCP пока не работает. Не заменяй вкладку, пока пользователь вводит пароль, и не выдавай открытие UI за успешную проверку MCP. На странице ошибки не оставляй пользователя: сообщи фактическую причину и следующий шаг. При отмене входа останови только запущенный тобой процесс.

## 6. Правила дальнейшей работы

Работай только с TOPTOP в пределах текущих персональных прав. Начинай рабочую задачу через навыки контекста и памяти, завершай структурированным итогом. Исторические знания отличай от текущих данных TREND; статус импортированных методик сохраняй.

На сервере действует срок 3 часа бездействия. Пользовательская работа продлевает сессию, фоновые проверки и обмен refresh сами срок не продлевают. Старое подключение без refresh требует одного повторного входа. Не обещай завершённую клиентскую проверку автоматического refresh: её статус и известные ограничения источников указаны в README.
